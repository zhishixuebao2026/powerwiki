# 需求与约定

这份文件记录**用户明确提出过的要求**，以及每一条现在是怎么落实、怎么验收的。
新接一套皮肤、或者改动生成流程之前先读这里，别踩已经踩过的坑。
更新记录见 `../CHANGELOG.md`，实现细节见 `../README.md`。

### 规则栏目四套皮肤怎么同步

规则换版时，`data/docs/` 的原文、`rules.html`、以及下面四套皮肤内嵌的正文必须一起换，且逐字一致：

| 皮肤 | 源文件 | 内嵌结构 | 同步工具 |
|---|---|---|---|
| 候星（规则默认页） | `skins/_source/observatory.html` | `Jx` 模板字符串，整份 Markdown | `tools/sync_rules_md.py` |
| 宣衡典章 | `skins/_source/xuanheng.html` | 同上 | `tools/sync_rules_md.py` |
| 朱版 | `skins/_source/zhuban.html` | `JSON.parse('[...]')` 块数组 | `tools/md_to_zhuban_ast.py` |
| 仪轨 | `skins/_source/xuanji.html` | `JSON.parse(y4)` 的 `{sections,toc}` | `tools/md_to_xuanji_ast.py` |

- 模板字符串会吃掉一层反斜杠：写入 `F\*` 必须二次转义成 `F\\*`，否则运行时退化成裸 `*` 触发斜体；
- 朱版 / 仪轨的块 id 与目录 id 是手工 slug，脚本按标题**复用原有 id**，不重新生成；

## 一·五、装成 App 的验收

> 定位：这是**给想自己把站点加到主屏幕的人**用的能力，不是站点主动推送的东西。
> 全站不出现任何「安装 / 添加到主屏幕」的提示、横幅、气泡或引导入口。

- `manifest` 能被取到，`display: standalone`、`start_url` 带 `?src=app`、图标齐全——手动「添加到主屏幕」照常可用；
- `apple-touch-icon` 180×180 存在，`apple-mobile-web-app-capable=yes`；
- service worker 注册成功并 `activated`，`caches` 里有壳层（离线能力照常保留，`#17` 验收不变）；
- 断开网络 / 停掉服务器后：已缓存页面照常打开，未缓存页面显示离线提示页，中文不出现方框；
- 独立窗口（`data-standalone`）下顶栏不被状态栏压住、底部不被 Home 指示条压住；
- **全站不得出现任何「安装 / 添加到主屏幕」的提示、横幅、浮层或引导入口**（这是本项与旧版最大的区别）；手动在浏览器里「添加到主屏幕」仍正常。

## 二、验收口径（每次都跑）

- 宽度 **1440 / 768 / 390 / 320** 各测一遍：
  - `document.documentElement.scrollWidth <= innerWidth`（横向溢出 0）
  - 页面无 JS 报错、无请求失败（`pageerror` / `requestfailed`）
  - 正文字数与上一版同量级（防止整段内容没渲染出来）
  - 深浅两套主题各截一张
- 固定元素两两求交必须为 0（印章 / 底栏 / 阅读工具条 / 抽屉）。
- 整页产物高度动辄上万像素：**抽样截图**（按比例取 8～9 屏拼图），
  不要按视口逐屏跑完整页那种全量扫描。

## 三、皮肤接入的固定流程

0. **先找到真正的构建产物，别急着自己 build**（2026-11-19 坑）：成品入口通常是 `dist/index.html`，
   但**也可能叫别的名字**（许青那套是 `dist/打开文库.html`）。先列全 dist 目录，看有没有
   几百 KB~几 MB、含 `data:image` base64 图 / 内联 bundle 的单文件；**只有 dist 里确实没有成品、
   根 `index.html` 又引用 `/src/main.tsx` 这类源码路径时**才 `npm install && npm run build`。
   （许青那套我误判为未构建、白跑一次 build；产物 md5 与 ZIP 原版一致、结果没错，但绕了远路。）
1. 产物整页 HTML 存成 `skins/_source/<id>.html`（自包含优先）；缺 `env(safe-area-inset-top)` 才补标准安全区；
2. `data/editions.json` 加一条：`id / name / tag / note / source / section|pages / thumb / patch`；
   - `section` 是栏目（rules / materials / …）；
   - 只挂单页时用 `pages` 里的单页键（例如 `character-yutu`），
     并在 `default` 那条里补同名键指回原页面，保证互跳；
   - **`inject: minimal`** 用于整页 React 应用，只注入切换器浮层，不污染应用自身样式与 DOM；
3. 字体缺失或有子集裁字时，构建期修（`font_rewrite` 或 patch 里换站内字体）；
   - 注意区分：`?inline` 外链但 dist 没落地 woff2 的（张衍两套），渲染会回退系统宋/黑体，
     实测视觉完整就**尊重原产物不擅改**；这是上传方工程特性，不是接入 bug。
4. 需要站内导航 / 避让 / 小样式修，全写进 `skins/patches/<id>.js`；
5. `python3 build_site.py` 重建，按第二节验收，再补 CHANGELOG 与 README 皮肤表。
6. **命名品味**（用户反复强调，见硬性要求 11 与下方补充）：走意象、古雅、贴合皮肤视觉。
   **禁止堆"颜色＋名词"**（"深蓝补天""黑金浑天仪"被指土），也**不要清一色两字古风词**
   （"怎么全是两个字，别重复了""怎么又二字八股文了"）。长短错落、有典故出处最佳。

### 皮肤升格为默认页的固定流程（2026-11-27 定，今后一律照做）

> 背景：玉兔「有时进会闪屏的旧默认」根因是构建走「先写标准页、再用皮肤整页覆盖」两步链路，
> 覆盖一旦没跑全就暴露旧页。现已对全部 7 个升格页根治。今后任何"把某皮肤设为默认"必须按下面做，
> **绝不允许再出现两步覆盖**。

1. **从源头不写标准页**，不要"先写后覆盖"：
   - 角色：`build_character_detail_pages()` 靠 `PROMOTED_CHARACTER_SLUGS` 跳过写 `character/<slug>.html`；
   - 规则/材质：`main()` 里 `build_fulltext_doc_page()` 只取 sections 不写 HTML，直接调升格函数写 `rules.html`/`materials.html`。
2. **写 `build_<栏目>_default_from_<皮肤>()` 整页函数**：读 `skins/_source/<皮肤>.html`，打 `data-pw-edition` 标记
   （月牍例外，用 `pw-moon-nav` 识别），注入 PWA/明暗桥接/切回角色档案/切换器 dock，写出目标默认页。
3. **升格源缺失必须硬失败**：函数开头 `if not src.exists(): raise RuntimeError(...)`，不许 `print WARN + return`
   静默留旧页（这正是旧默认复活的温床）。
4. **加入三处登记，缺一不可**：
   - `edition_launcher_html()` 里的 `promoted_defaults` 集合加皮肤 id（防回填成可切换卡片）；

   - `main()` 的 `promoted_guards` 断言表加 (相对路径, 识别标记)。
5. **从 `editions.json` 移除该皮肤的可切换条目**，删除 `skins/<id>/` 产物，只留 `skins/_source/<id>.html`；
   同步更新 README 皮肤数（升格一套即 -1）。
6. **验证三件套**：①构建成功且 `promoted_guards` 断言全过；②负向测试——临时藏掉升格源，构建必须退出码≠0；
